# 0001. 소견서·EMR 서술 문구의 정본

- 상태: **결정 대기** — 사용자가 아래 표의 "정본" 칸을 채운다
- 관련: `docs/REFACTORING_ROADMAP.md` Phase 2 C7(서술 단일 소스) — C7-a(P2-59 ~ P2-65b)가 이 표를 만들고, 게이트 C 뒤 P2-66이 정본이 적힌 행만 통일한다

## 배경
같은 평가 결과를 세 출력처가 따로 문장으로 만든다.

| 변형 | 출력처 | 만드는 곳 |
|---|---|---|
| `report` | 업무관련성 통합 평가 보고서(소견서 텍스트) | `src/core/utils/reportGenerator.js` → 모듈 서술 |
| `emrSection` | EMR 4번 칸(직업적 요인, b6 `txtJobCusCont`) — 전문 | `src/core/utils/emrReport.js` `buildExposureSection` → 모듈 서술 |
| `emrSummary` | EMR 6번 칸(종합소견, b8 `txtSyth1Cont`) — 요약(EMR 글자 수 절감) | `emrReport.js` `buildExposureSummary` → 모듈 서술 |

C7-a에서 모듈별 서술을 각 모듈의 `src/modules/<id>/narrative.ts`로 **문구를 바꾸지 않고** 옮겼고(골든 불변), 변형마다 달라지는 문자열을 `narrative.phrases[항목][변형]` 표로 뺐다. 아래 표 A는 그 표에서 **변형 사이에 값이 다른 행**을 그대로 뽑은 것이다(`node scripts/narrative-diff.mjs`). 표로 표현되지 않는 코드 구조의 차이는 표 B에 따로 적었다.

지금의 차이가 모두 실수는 아니다 — b8은 EMR 글자 수 제한 때문에 일부러 짧게 만든 요약이고, 들여쓰기는 소견서 문서 형식에 맞춘 것이다. 그래서 **정본을 적은 행만** 통일하고 나머지는 지금 그대로(차이 유지) 둔다(사용자 결정 2026-11-14 "결정 8").

## 표 읽는 법
- 값은 JSON 문자열 표기다 — `\n`은 줄바꿈, 따옴표 안의 공백은 실제 공백(들여쓰기)이다. `—`는 그 변형이 그 항목을 쓰지 않는다는 뜻이다.
- `{n}` = 직력 번호, `{name}` = 직종명(빈 값이면 `jobNameEmpty` 행의 값)이다.
- "정본" 칸에 적는 방법: `report`·`emrSection`·`emrSummary` 중 하나(그 값으로 맞춤) · 새 문구(따옴표로) · `유지`(차이를 그대로 둠 — 이유를 한 줄로). 비워 두면 P2-66에 들어가지 않는다.
- 통일하면 그 출력처의 문장이 바뀐다(골든 `report-text`·`emr`·`export-files`와 보강 골든이 바뀌는 **flagged** 변경). EMR은 글자 수 상한(CP949 바이트)이 있어, b8을 b6처럼 길게 맞추는 선택은 잘림 위험이 커진다.

## 이 표 밖의 같은 종류 차이(참고 — 출력처 차이가 아니거나 C7-a 범위 밖)
1. **어깨 해석 문장의 다섯 번째 판**: 소견서·b6·b8의 해석 문장 3가지는 이미 같다(표 A에 나오지 않는 이유 — `node scripts/narrative-diff.mjs --all`의 "같음" 행). 판정 규칙은 C7-a에서 analytics-core `classifyBk2117Interpretation` 한 곳으로 모았다(P2-61a). 서버의 AI 프롬프트 계약(`shared/contracts/aiPrompt.ts`의 `SHOULDER_INTERPRETATION_LABELS`)에는 문장이 다른 판이 하나 더 있다(예: 초과 = "개별 기준 초과 항목이 있어 누적 신체부담은 충분함", 쉼표·`**` 없음). 프롬프트 계약이라 C7-a에서는 바꾸지 않았다 — 맞출지 여부는 이 문서와 별도로 정한다.
2. **모듈 사이 라벨 차이**(같은 출력처 안에서 팔꿈치와 손목이 다름 — analytics-core의 계산 라벨): 노출 수준 `mild` = 팔꿈치 '경미' / 손목 '경도', `occasional` = 팔꿈치 '간헐적' / 손목 '가끔'(`packages/analytics-core/modules/{elbow,wrist}/derived.ts`). C7-a 범위 밖.
3. 처음 계획에 차이 후보로 적었던 '연령 대비 경미'(띄어 쓴 형태)는 저장소에 없다. 저소견 사유 라벨은 '연령대비 경미' 한 가지다.
4. 팔꿈치는 `temporalFlagsLead`·`riskFactorLabel`이 소견서와 b6에서 같고, 손목만 다르다(표 A 10·14행) — 정본을 정하면 두 모듈을 함께 맞출 수 있다.

## 결정
**2026-11-26 사용자 결정** — 표 A 24행과 표 B 11행(B1 ~ B11)의 "정본" 칸을 모두 채웠다(B12는 결정 불필요). 비워 둔 행은 없다.

- 표 A: `report` 3행(11·17·22 — 직력 줄 형식) · `emrSection` 10행(2·6·7·8·9·10·14·15·20·21) · `emrSummary` 6행(1·12·16·18·23·24) · 유지 5행(3·4·5·13·19).
- 표 B: `report` 4행(B1·B6·B8·B9) · `emrSection` 3행(B2·B7·B10) · `emrSummary` 2행(B3·B4) · 유지 2행(B5·B11).
- 유지로 둔 행의 이유는 따로 받지 않았다.

**P2-66 계획에서 먼저 확인할 것**(계획 세션의 메모 — 사용자 결정이 아니다):

1. B6·B8·B9를 `report`로 맞추면 EMR 6번 칸의 어깨·팔꿈치·손목·경추 블록이 요약에서 전문으로 늘어난다(무릎 B5·척추 B11은 요약 유지). EMR 글자 수 상한(CP949 바이트)에 대해 골든·보강 환자로 길이를 재고, 넘는 경우가 있으면 사용자에게 다시 묻는다.
2. B8을 `report`로 맞추면 6번 칸이 `narrativeEmpty`(표 A 13·19행, 유지)를 새로 쓰게 된다. 그 변형의 값(`""` 또는 `"-"`)은 정해지지 않았다.
3. 표 A 11·17·22행(`report`): EMR 두 칸의 직력 줄에 직력 번호가 들어간다. 지금은 소견서만 번호 맵을 받는다.
4. 표 A 6행(`emrSection`): 소견서의 "참고)" 앞 빈 줄은 지금 문구 표 밖에서 만든다. 직력 사이 빈 줄을 맞춘 뒤에도 "참고)" 앞 빈 줄이 한 줄로 남게 한다.
5. B1(`report`): EMR의 모듈 순서가 환자의 평가 부위 선택 순서를 따르게 된다. C7-a에서 넣은 고정 순서(`narrative.emrOrder`)와 그 단위 테스트의 처리를 정한다.
6. B3(`emrSummary`): 소견서의 머리글 표기만 `[ 업무관련성 평가 결과 ]`로 바꾼다. EMR 4번 칸에는 이 머리글을 추가하지 않는다.
7. B4(`emrSummary`): 소견서에서도 직종명이 빈 무릎 직력을 뺀다(지금의 `직종: -` 줄이 없어진다).

## 결과
- 정본이 적힌 행만 P2-66(게이트 C 뒤, 1~3 PR)에서 통일한다 — 모듈의 `narrative.phrases` 값과(구조 차이면) 서술 코드를 고치고, 골든을 `-u`로 갱신해 PR에 diff와 이유를 적는다(flagged). EMR 주입은 손으로 확인한다.
- 문구 차이 표는 `src/core/narrative/__tests__/__goldens__/narrative-diff.json`(vitest가 얼림)이 원본이다. 모듈 서술의 문구가 바뀌면 이 골든이 먼저 깨진다. 사람이 읽는 표는 `node scripts/narrative-diff.mjs`(`--all`: 같은 행 포함, `--out <파일>`)로 다시 뽑는다.
